# Project Format

Projects live in `./projects/` and use sequential numbering: `0001-slug.html`, `0002-slug.html`, etc. A project is a small, self-contained exercise that reinforces a lesson by having the user *build* something — not just recall facts.

## What is a project?

A project is:
- A hands-on task tied to a specific lesson
- Something the user completes and can show or run
- Scoped to be completable in one sitting (15-30 minutes)
- More effortful than a quiz — requires synthesis, not just recall

A project is NOT:
- A full application or portfolio piece
- Open-ended with no clear success criteria
- A replacement for lessons — it complements them

## Template

Each project file (`./projects/0001-slug.html`) should contain:

1. **Goal** — One sentence: what the user will build or do
2. **Context** — Why this matters, tied to the mission
3. **Requirements** — Numbered list of concrete deliverables
4. **Steps** — Guided walkthrough (not a solution — prompts the user to think)
5. **Success criteria** — How the user (and agent) know it's done
6. **Extension** — Optional: a harder variation for users who finish early

## Rules

- **One project per lesson, maximum.** Not every lesson needs a project. Only add one when the lesson teaches a skill that benefits from application.
- **Keep it small.** If the project takes more than 30 minutes, split it.
- **Tie to the mission.** The project should feel useful, not academic.
- **Provide feedback.** The agent should review the completed project and give actionable feedback.
- **Track completion.** When a project is completed, record it in the next learning record as evidence of skill acquisition.
